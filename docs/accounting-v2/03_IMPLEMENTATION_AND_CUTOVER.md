# التنفيذ والتحقق وخطة التحول

## ملفات التنفيذ المضافة

- `database/migrations/2026_11_19_180000_create_finance_v2_ledger_tables.php`
- `app/Models/Finance/*`
- `app/Services/Finance/LedgerPostingService.php`
- `app/Services/Finance/FundBalanceService.php`
- `app/Services/Finance/CashTransferService.php`

## ضمانات الكود

### `LedgerPostingService`

- يرفض أقل من سطرين، والسطر الذي يحمل مديناً ودائناً معاً أو صفراً، والقيد غير المتزن.
- يقفل الفترة والحسابات المختارة، ويرفض الحساب غير الفعال أو التجميعي.
- يمنع التكرار عبر `idempotency_key`.
- ينشئ الرأس والسطور في transaction واحدة.
- العكس ينشئ قيداً جديداً معكوساً مرتبطاً بالأصل؛ لا يعدّل الأصل ولا توجد دالة update/delete للقيد المرحل.

### `FundBalanceService`

- يقفل صف الرصيد `FOR UPDATE` ثم يسجل الحركة ويحدث projection في transaction واحدة.
- يرفض الاستهلاك الذي يتجاوز المتاح للصندوق، إلا عندما تسمح سياسة الصندوق بالسالب.

### `CashTransferService`

- التحويل يبدأ `submitted` فقط؛ لا يولد أثراً محاسبياً عند إنشائه.
- الاستلام يؤمن الحسابين، وينشئ قيد تحويل متزناً، ثم يضع الحالة `received` في transaction واحدة.

## خطة قطع التشغيل

1. **تجميد تغييرات V1:** حظر create/update/delete المالي في الواجهات القديمة بعد إعلان تاريخ القطع.
2. **جرد:** عد النقد، الحصول على كشف البنك والمحافظ، مراجعة الشيكات والتحويلات والعهد والالتزامات.
3. **خريطة الحسابات:** اعتماد mapping لكل خزينة فعلية إلى `cash_account` وحساب GL، ولكل غرض متبرع إلى `fund`.
4. **فتح فترة وترحيل افتتاحي:** قيد افتتاحي واحد متزن ومعتمد لكل عملة؛ لا تعديل `opening_balance` القديم.
5. **ترحيل تاريخي:** حفظ `source_type/source_id` لكل سجل V1، وفصل الاستثناءات في كشف تسوية بدلاً من اختراع تاريخ جديد.
6. **تشغيل مزدوج:** فترة يومية/أسبوعية قصيرة تقارن النقد الفعلي ودفتر V1 وV2 وكشف البنك والصناديق.
7. **اعتماد وتبديل:** يعتمد المدير المالي والمراجع الداخلي محضر التطابق ثم يصبح V1 للقراءة فقط.

## اختبارات قبول لازمة قبل التبديل

| الاختبار | النتيجة المطلوبة |
|---|---|
| محاولة قيد غير متزن | رفض كامل بلا أي صف محفوظ |
| إعادة إرسال نفس idempotency | يعيد نفس القيد دون تكرار |
| مصرف في فترة مغلقة | رفض كامل |
| عكس قيد مرتين | الرفض في المرة الثانية |
| تحويل قبل استلام المستفيد | لا قيد ولا حركة نقدية |
| تحويل عند الاستلام | قيد مدين/دائن واحد متزن |
| استهلاك صندوق مقيد يتجاوز المتاح | رفض مع بقاء الرصيد والحركة كما هما |
| عمليتا صرف متزامنتان | لا يتجاوز أي منهما النقد/الصندوق المتاح |
| منشئ طلب اعتماد نفسه | رفض على مستوى سياسة الموافقات |

## التحقق المنفذ لهذا التغيير

تم تشغيل `php -l` على الهجرة وكل موديلات وخدمات V2 الجديدة، ونجح الفحص. كما نجح تحميل قائمة مسارات الخزائن (`php artisan route:list --path=treasuries`). لم ينفذ `migrate` على قاعدة الإنتاج أو على بيانات المستخدم؛ ذلك متعمد، لأن التحول المالي يحتاج جرداً وتاريخ قطع معتمداً.
