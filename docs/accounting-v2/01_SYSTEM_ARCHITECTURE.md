# هيكل نظام الحسابات الجديد — Ensan Finance V2

## وحدات النظام ومسؤوليتها الدقيقة

| الوحدة | الكيان المسؤول | ما تفعله | ما لا تفعله |
|---|---|---|---|
| دليل الحسابات | `financial_accounts` | تصنيف الأصل والالتزام وصافي الأصول والإيراد والمصروف | لا يحتفظ برصيد يدوي |
| الدفتر العام | `ledger_entries` و`ledger_entry_lines` | مصدر الحقيقة لكل أثر مالي مرحّل | لا يقبل تعديل/حذف القيد المرحّل |
| الحسابات النقدية | `cash_accounts` | الصندوق، البنك، المحفظة، والنقد بالطريق فقط | لا يمثل مشروعاً أو حملة |
| الصناديق المقيدة | `funds` و`fund_balances` و`fund_movements` | متابعة ما يسمح بصرفه وفق شرط المتبرع | لا يزيد إجمالي النقد |
| التوريد والتحويل | `cash_transfers` | تسليم ثم استلام ثم قيد تحويل واحد | لا يسجل إيراداً/مصروفاً |
| العهد | `custodies` و`custody_expenses` | ذمة موظف وتسوية فواتير ورد متبقٍ | لا يجعل التسليم مصروفاً |
| البنك | `bank_reconciliations` و`bank_reconciliation_lines` | مطابقة كشف البنك واعتماد الفروق | لا يعدل الرصيد لإخفاء الفرق |
| السندات | `financial_documents` | ترقيم وحالة وإبطال موثق للسند | لا يعيد استخدام الرقم |
| الموافقات | `financial_approvals` | maker-checker ومراحل القرار | لا يسمح باعتماد المنشئ لنفسه |

## فصل الدلالات المالية

```text
تبرع مؤكد ──► حساب نقدي فعلي ──► قيد أستاذ متزن
                   │                         │
                   │                         └── أبعاد: صندوق، مشروع، حملة، مستفيد، فرع
                   └── لا يرتفع بسبب تخصيص المشروع

صندوق/مشروع/حملة = التزام غرض ومتابعة إنفاق، وليس موقعاً للنقد
```

## تدفقات الأعمال الإلزامية

### 1. التبرع النقدي أو الإلكتروني

1. يسجل التبرع مع وسيلة التحصيل وإثباته وحالة التحقق.
2. يثبت وصوله إلى صندوق/محفظة/بنك فعلي.
3. يعتمد مستلم مختلف عن منشئه؛ ينشأ سند قبض وقيد: مدين نقد فعلي، دائن إيراد/صافي أصول مقيد.
4. تسجل تخصيصاته كسطور normalized إلى الصندوق/المشروع/الحملة؛ مجموعها يساوي التبرع عند الاعتماد.
5. لا تضاف قيمة أخرى إلى «خزينة المشروع».

### 2. توريد أو إيداع أو تحويل داخلي

`draft → submitted → handed_over → received → approved/reconciled`، مع مسار `discrepancy/rejected/cancelled`.

- القيد لا ينشأ عند الطلب ولا عند التسليم فقط، بل عند الاستلام المؤكد: مدين المستلم، دائن المصدر.
- فرق الاستلام يعالج بقيد تسوية مستقل ذي سبب وموافقة؛ لا يغير الرصيد الافتتاحي.
- ربط الإيصالات بالتوريد يمنع توريد الإيصال نفسه مرتين ويدعم التوريد الجزئي المصرح.

### 3. المصروف والتحويل البنكي والشيك

1. طلب مصروف وبنود توزيع إلى مشروع/حملة/صندوق ومرفقات وموافقة.
2. فحص النقد المتاح والصندوق المقيد مع قفل الصفوف.
3. التحويل/الشيك يبقى pending حتى تأكيد البنك؛ لا يصبح مصروفاً نهائياً إذا فشل أو ارتجع.
4. عند النجاح: مدين حساب المصروف أو المساعدة، دائن البنك/النقد، وتخفيض رصيد الصندوق بالتزامن.

### 4. العهدة

- التسليم: مدين عهد موظفين، دائن النقد؛ لا مصروف.
- فواتير التسوية المعتمدة: مدين مصروف موزع، دائن عهدة الموظف.
- المتبقي: مدين النقد، دائن عهدة الموظف.
- فرق مستحق للموظف لا يدفع تلقائياً؛ يصبح التزاماً/طلب دفع مع اعتماد.

## عناصر الحوكمة

- صلاحيات الحساب النقدي ليست صلاحية شاشة: view, receive, disburse, transfer, reconcile.
- مستخدم واحد لا ينشئ ويستلم ويعتمد ويطابق الحدث ذاته.
- تمنع الفترات غير المفتوحة أي ترحيل أو عكس؛ إعادة الفتح إجراء منفصل.
- كل أمر خارجي يحمل `idempotency_key`، وكل تصحيح ينشئ `reversal_of_id` لا تعديل الأصل.
- ينشر التقرير فقط من دفتر V2؛ `current_balance` القديم لا يعد مصدراً رسمياً.

## واجهات التقارير اللازمة

1. ميزان مراجعة ودفتر أستاذ وكشف حركة الحساب النقدي.
2. رصيد نقد فعلي حسب الخزينة/البنك/المحفظة؛ لا يضم المشاريع.
3. أموال مقيدة وغير مقيدة ومتاحة ومحجوزة لكل صندوق.
4. التحصيل إلى الصرف: من إيصال التبرع إلى التوريد إلى الصرف أو الرصيد المتبقي.
5. تحويلات معلقة وفروق توريد وشيكات وحوالات لم تؤكد.
6. عهد مفتوحة ومتأخرة وفواتير مرفوضة ومتطلبات رد.
7. تقرير استثناءات ومطابقة بنك/محفظة، مع توقيع المراجع.
